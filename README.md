# Smart Helpdesk

Веб-система учёта заявок в техподдержку. Сотрудники создают заявки, агенты их ведут и закрывают, администратор управляет пользователями и справочниками. При создании заявки модель машинного обучения предлагает категорию по тексту, а руководитель видит отчёты по срокам и качеству классификации.

**Стек:** FastAPI, SQLAlchemy 2.0, PostgreSQL 16, React, TypeScript, Vite, Ant Design, Recharts, TanStack Query, scikit-learn, Docker Compose.

## Возможности

- Регистрация сотрудников и вход по логину и паролю
- Создание заявок, статусы, назначение исполнителя
- Комментарии и внутренние заметки, которые автор заявки не видит
- Автоматическая категория от модели: её можно подтвердить или исправить
- Срок решения по приоритету (SLA), просроченные заявки выделяются
- Дашборд с графиками и отчёт по срокам

## Роли

| Роль | Что может |
|---|---|
| Сотрудник | зарегистрироваться сам, создавать заявки, видеть свои заявки, писать комментарии |
| Агент поддержки | видеть все заявки, брать в работу, менять статус, категорию и приоритет, писать внутренние заметки. Создаёт администратор |
| Администратор | всё, что умеют агенты, плюс управление пользователями и справочниками. Первый создаётся скриптом |

Жизненный цикл заявки:

```
Новая → В работе → Ожидает ответа → В работе → Решена → Закрыта
```

«Решена» и «Закрыта» финальные: после них заявка не меняется.

## Состав проекта

| Компонент | Что делает | Где лежит |
|---|---|---|
| PostgreSQL | хранит пользователей, заявки, комментарии, справочники и предсказания модели | контейнер `db` в `docker-compose.yml` |
| API на FastAPI | принимает запросы, проверяет права, применяет бизнес-правила | `backend/app/` |
| Классификатор | предлагает категорию по тексту заявки: TF-IDF и логистическая регрессия | `backend/ml/` |
| Веб-интерфейс | страницы для сотрудников, агентов и администратора | `frontend/src/` |
| Миграции | меняют схему базы без потери данных | `backend/migrations/` |
| Docker Compose | поднимает базу и API одной командой | `docker-compose.yml`, `backend/Dockerfile` |

Внутри API запрос проходит слои сверху вниз: `routers/` принимает запрос и проверяет права, `schemas/` проверяет данные, `services/` применяет бизнес-правила (сроки, статусы, исправления модели), `models.py` работает с таблицами. Классификатор загружается при старте API, сервис заявок вызывает его при создании заявки.

Пароли хранятся только в виде хеша. Вход выдаёт токен JWT, который подписан `JWT_SECRET`.

## API

Все адреса, кроме `/health`, `/auth/login` и `/auth/register`, требуют заголовок `Authorization: Bearer <токен>`. Полное описание с примерами запросов и ответов доступно в Swagger.

| Метод | Путь | Описание |
|---|---|---|
| POST | `/auth/register` | регистрация сотрудника, роль назначается автоматически |
| POST | `/auth/login` | вход, возвращает токен |
| GET | `/health` | проверка подключения к базе |
| GET, POST | `/tickets` | список с фильтрами и создание заявки |
| GET, PATCH | `/tickets/{id}` | карточка и изменение заявки |
| GET, POST | `/tickets/{id}/comments` | комментарии |
| GET | `/priorities`, `/categories`, `/statuses` | справочники |
| GET, POST, PATCH | `/users` | управление пользователями (администратор) |
| GET | `/reports/dashboard`, `/reports/sla` | данные для дашборда и отчёта по срокам |

## Требования

- Docker Desktop (Windows, macOS) или Docker Engine с Compose (Linux): https://docs.docker.com/get-started/
- uv, менеджер Python: https://docs.astral.sh/uv/getting-started/installation/ (сам установит Python 3.12)
- Bun для фронтенда: https://bun.sh
- Git: https://git-scm.com

Команды выполняйте в терминале. В Windows подойдут PowerShell или Git Bash.

## Запуск

### 1. Скачать проект

```bash
git clone https://github.com/<логин>/smart-helpdesk.git
cd smart-helpdesk
```

### 2. Создать `.env`

Скопируйте шаблон (в PowerShell: `copy .env.example .env`):

```bash
cp .env.example .env
```

Заполните значения:

| Переменная | Что написать |
|---|---|
| `POSTGRES_USER` | логин для базы, например `helpdesk` |
| `POSTGRES_PASSWORD` | длинный пароль |
| `POSTGRES_DB` | имя базы, например `helpdesk` |
| `JWT_SECRET` | случайная строка, см. ниже |
| `CORS_ORIGINS` | `http://localhost:5173` |
| `ADMIN_USERNAME` | логин первого администратора |
| `ADMIN_PASSWORD` | пароль первого администратора |

Случайную строку для `JWT_SECRET` создайте командой:

```bash
cd backend
uv run python -c "import secrets; print(secrets.token_hex(32))"
cd ..
```

Файл `.env` содержит пароли, его нельзя коммитить.

### 3. Поднять базу и API

Из корня проекта:

```bash
docker compose up --build -d
docker compose ps
```

Сервис `db` должен стать `healthy`, `api` должен работать. Первая сборка занимает несколько минут.

### 4. Создать таблицы и администратора

Из папки `backend/`:

```bash
cd backend
uv sync
uv run alembic upgrade head
uv run python scripts/seed.py
cd ..
```

- `uv sync` ставит зависимости из `uv.lock` в окружение проекта;
- `alembic upgrade head` создаёт таблицы;
- `seed.py` заполняет приоритеты, категории и статусы и создаёт администратора из `ADMIN_USERNAME` и `ADMIN_PASSWORD`.

### 5. Обучить классификатор

Датасет лежит в `backend/data/`. Обучение запускается один раз:

```bash
cd backend
uv run python ml/train.py
cd ..
```

Скрипт выведет точность и F1-меру и сохранит модель в `backend/ml/artifacts/`. Без модели заявки создаются, но категория не предлагается. После переобучения перезапустите API: `docker compose restart api`.

### 6. Запустить веб-интерфейс

```bash
cd frontend
bun install
bun run dev
```

Откройте http://localhost:5173. Сотрудник регистрируется на странице «Регистрация». Администратор входит под логином из `.env`, создаёт агентов и управляет справочниками.

### Проверка

- `curl http://localhost:8000/health` возвращает `{"status":"ok","database":"connected"}`;
- Swagger с описанием всех эндпоинтов: http://localhost:8000/docs.

### Остановка

```bash
docker compose stop      # остановить, данные сохраняются
docker compose start     # запустить снова
docker compose down      # удалить контейнеры, данные сохраняются
docker compose down -v   # удалить контейнеры и все данные базы
```

Веб-интерфейс останавливается сочетанием `Ctrl+C`.

## Частые проблемы

| Симптом | Что сделать |
|---|---|
| `Field required` для `postgres_user` и других | `.env` не найден или переменные названы иначе; `.env` должен лежать в корне, рядом с `docker-compose.yml` |
| `password authentication failed` | пароль в `.env` не совпадает с тем, с которым создана база; верните старый пароль или выполните `docker compose down -v` (данные удалятся) |
| `/health` отвечает `503` | база не запущена: `docker compose up -d db`, затем `docker compose ps` |
| `port is already allocated` | порт 5432 или 8000 занят; остановите другую программу или поменяйте порт в `docker-compose.yml` |
| Браузер пишет CORS-ошибку | адрес фронтенда отсутствует в `CORS_ORIGINS`; добавьте его и выполните `docker compose restart api` |
| `401 Unauthorized` после входа | токен истёк, войдите заново |
